# NINO research | โมเดลภาษาที่เราสร้างเอง (งานวิจัย ยังไม่ใช่ส่วนของแอป)

เป้าหมาย: เรียนรู้และทดสอบได้จริงว่าโมเดลภาษาเล็กที่เขียนเองทำอะไรได้บ้าง โดยไม่พึ่งโมเดลสำเร็จรูปภาษาอังกฤษ
โค้ดทั้งหมดเป็น numpy ล้วน (เครื่องนี้ไม่มี torch และติดตั้งแพ็กเกจไม่ได้) ไม่ได้อยู่ในแอป ไม่ได้ถูกโหลดจาก index.html

## ไฟล์
- `charlm.py`: โมเดลระดับตัวอักษร (MLP แบบ Bengio) backprop เขียนเอง Adam ควอนไทซ์ int8 รายคอลัมน์ การสุ่มตัวอย่าง
- `test_charlm.py`: gradient check (ผลต่างสัมพัทธ์ < 1e-5), ค่าเริ่มต้นใกล้ log(V), เรียนรู้รูปแบบซ้ำได้, int8 ผิดไม่เกินครึ่งขั้น, การสุ่มกำหนดได้
- ผลลัพธ์ที่เขียนลง `out/` จากคำสั่ง `experiment` ไม่เก็บในซิป สร้างใหม่ได้ด้วยคำสั่งเดิม

## ผลการทดลอง (ข้อความไทยจากเอกสารในรีโป 160,780 ตัวอักษร, แบ่งท้าย 10% เป็นชุดทดสอบ)
| รุ่น | bits/char บนชุดทดสอบ |
|---|---|
| unigram | 6.353 |
| bigram (add-0.5) | 4.659 |
| MLP ลอยจุด (พารามิเตอร์ 42,902) ดีที่สุดที่ epoch 16 | 3.989 |
| MLP หลัง int8 | 3.993 (ต่างจากลอยจุด +0.004) |

สังเกต:
- โมเดลชนะ bigram ตั้งแต่ epoch 1 แต่หลัง epoch 16 เริ่ม overfit: train ลดต่อ ส่วน val ขึ้น (ระบบเลือกน้ำหนักที่ val ดีที่สุดอัตโนมัติ)
- int8 ต่างจากลอยจุดเพียงเล็กน้อย จึงเป็นทางไปสู่การรันบนมือถือที่คุ้มค่าเรื่องขนาด
- ผลลัพธ์ที่สุ่มออกมาเป็นภาษาไทยรูปร่างคล้ายประโยค แต่ความหมายไม่มี เพราะข้อมูลน้อยมากและเป็นเรื่องพัฒนาแอป ไม่ใช่บทสนทนาทั่วไป

## ข้อจำกัด
- ข้อมูลน้อย (ประมาณ 1.6 แสนตัวอักษร) และเป็นโดเมนเดียว ทำให้คุณภาพไม่ใกล้โมเดลภาษาจริง
- ยังไม่มี attention ตัวอักษรระดับเดียวไม่เห็นบริบทไกล
- ยังไม่ได้วัดการตอบคำถาม ใช้เพียง bits/char และการอ่านตัวอย่างด้วยตา

## ขั้นต่อไปที่เสนอ
1. ข้อความไทยที่มากขึ้นและหลากหลาย (ผู้ใช้ให้ไฟล์หรือลิงก์ที่อนุญาต)
2. ตัวตัดคำระดับพยางค์แทนตัวอักษร (ลดลำดับยาว ให้โมเดลเห็นบริบทมากขึ้นต่อขนาด)
3. ทรานส์ฟอร์เมอร์ชั้นเดียวที่มี attention เขียน backprop เองและตรวจด้วย gradient check เหมือนเดิม
4. รูปแบบตัวเลขที่ต่ำกว่า int8 (เช่น fp8 แบบจำลอง) และวัดผลเทียบกัน
