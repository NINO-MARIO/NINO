# วิจัย NDS: สิ่งที่ตรวจแล้ว กับสิ่งที่ยังต้องตรวจ

ป้ายกำกับ:
- [ตรวจแล้ว: โค้ด] ยืนยันจากโค้ดในรีโปนี้ (ไฟล์ระบุไว้)
- [ความจำ: ยังไม่ตรวจ] มาจากความรู้ทั่วไปเรื่อง DS ยังไม่ได้เทียบกับเอกสารต้นฉบับ (เครื่องนี้ไม่มีอินเทอร์เน็ต)

## 1. เวลาและเสียง
- [ตรวจแล้ว: nds/sync.go] cBusClock = 0x1FF61FE (33.513982 MHz), cAudioFreq (CAudioFreq) = 32768 Hz
- ห้อง NDS ตั้ง AUDIO_RATE = 32768 และ 2 ช่องให้ตรงกัน (games/nds/core-contract.js)

## 2. การอ่านปุ่ม (KEYINPUT) ไม่ตรงกันระหว่างเอนจินกับห้อง
- [ตรวจแล้ว: nds/key.go ReadKEYIN] เอนจินอ่านจาก KeyState (รหัส SCANCODE) โดยตรง และเป็นแบบ active-low (กดแล้ว bit ถูกเคลียร์)
  - bit0 ← Z, bit1 ← X, bit2 ← RSHIFT, bit3 ← RETURN, bit4 ← RIGHT, bit5 ← LEFT, bit6 ← UP, bit7 ← DOWN, bit8 ← A, bit9 ← S
- [ตรวจแล้ว: games/nds/player.js] ห้องส่ง setKeys(mask) แบบ active-high ตามลำดับ KEYINPUT ดังนี้ bit0 A, bit1 B, bit2 SELECT, bit3 START, bit4 RIGHT, bit5 LEFT, bit6 UP, bit7 DOWN, bit8 R, bit9 L, bit10 X, bit11 Y
- [ทำแล้ว: nds/key.go] SetKeyMask(mask) เก็บ mask ตามลำดับ KEYINPUT และ ReadKEYIN/ReadEXTKEYIN รวมมันกับคีย์บอร์ด (X=bit0 และ Y=bit1 ของ EXTKEYIN ตามที่โค้ดเดิมใช้กับ D และ C). ยังไม่มีการต่อจาก setKeys ของ wasm (รอ wasm/ เรียกเอนจิน)
- [โค้ด + ความจำ] ที่ ReadEXTKEYIN ใช้บิต 0 กับ 1 สำหรับ X กับ Y สอดคล้องกับความจำเรื่อง DS แต่ยังไม่ได้ยืนยันกับเอกสารต้นฉบับ
- ความต่างของปุ่มเริ่มต้น: เอนจินเดสก์ท็อปแมป A=Z, B=X ส่วนห้องแมป A=X, B=Z (ตามที่ emulator ทั่วไปใช้) ต้องตัดสินใจตอนเชื่อม
- [ทำแล้ว: nds/key.go] ตัด log.ModInput ที่เรียกทุกครั้งที่อ่านปุ่มออกแล้ว (ข้อ 5)

## 3. จอและเค้าโครง
- [ความจำ: ยังไม่ตรวจ] จอ DS สองจอ จอละ 256 × 192 พิกเซล จอล่างคือจอสัมผัส
- ห้องใช้ framebuffer 256 × 384 (จอบนแถว 0..191, จอล่างแถว 192..383) เป็นข้อสมมติในสัญญา ยังไม่ได้ตรวจกับโค้ดเรนเดอร์จริง
- [ยังไม่ตรวจ: nds/lcd.go] การจัดเรียงจอบนล่างในโค้ดเอนจิน ต้องเปิดไฟล์นี้ก่อนยืนยัน

## 4. การ์ดและ header
- [สร้างเอง: tools/test/fixtures/nino-test.nds] ตำแหน่งชื่อ 0x00 และรหัส 0x0C ที่ห้องอ่าน และ CRC 0x15E ตรวจโดยคำนวณซ้ำในสคริปต์สร้างไฟล์ (ยืนยันการสอดคล้องกับไฟล์ที่เราสร้าง ไม่ใช่กับเอนจิน)
- [ความจำ: ยังไม่ตรวจ] ตำแหน่ง ARM9 entry 0x24, ARM7 entry 0x34, secure area ที่ 0x4000 ซึ่งเข้ารหัสในตลับเชิงพาณิชย์
- [ตรวจแล้ว: nds/encryption.go, gamecard.go] ตารางการเข้ารหัสมาจาก BIOS ARM7 (key1) ซึ่ง FreeBIOS ไม่มี

## 5. ปัญหาด้านประสิทธิภาพที่พบในโค้ดเอนจิน
- [ตรวจแล้ว: nds/key.go] ReadKEYIN เคยเรียก log ทุกครั้งที่อ่านปุ่ม (แก้แล้ว ดูข้อ 2)

## 6. คำถามที่ยังเปิดอยู่ (ลำดับความสำคัญ)
1. [ทำแล้ว] ปุ่มส่งมาทาง mask ผ่าน SetKeyMask. ที่เหลือคือต่อ setKeys ของ wasm เข้ากับ SetKeyMask
2. ตรวจตำแหน่ง framebuffer และจอบน/ล่างในโค้ด lcd.go (ข้อ 3)
3. ตรวจ header offset ARM9/ARM7 entry และขนาดตลับ กับโค้ด gamecard.go (ข้อ 4)
4. secure area: ตลับเชิงพาณิชย์ต้องการตาราง key1 จาก BIOS จริง เป็นข้อจำกัดทางกฎหมายที่ผู้ใช้ต้องนำเข้าเอง

## ข้อจำกัดของการวิจัยนี้
- ไม่มีอินเทอร์เน็ตในเครื่องนี้ จึงไม่ได้เทียบกับเอกสาร DS จริง ทุกข้อที่เป็น [ความจำ] ต้องยืนยันก่อนใช้
- ไม่มี Go ทำให้รันโค้ดเอนจินไม่ได้ ข้อ [ตรวจแล้ว: โค้ด] คือการอ่านโค้ด ไม่ใช่การรัน
