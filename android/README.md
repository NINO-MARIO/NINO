# NINO Android (แอปจริง ไม่ใช่ตัวห่อเว็บแบบเดิม)

## มันคืออะไรตอนนี้ (เฟส 1)
โปรเจกต์ Android เนทีฟ (Kotlin + Gradle) ที่มีแกนเนทีฟของตัวเอง ลายเซ็นของตัวเอง และบิลด์ด้วย GitHub Actions ไม่ต้องใช้คอม
- **หน้าจอ UI ยังเป็นเว็บชุดเดิม** แต่รันใน WebView ที่ล็อกแน่น ที่ `https://appassets.androidplatform.net` (ต้นทางของแอปเอง ไม่ใช่ github.io ที่ใช้ร่วมกับเว็บอื่น) แล้วค่อยย้ายทีละหน้าเป็นเนทีฟในเฟส 3
- **แกนเนทีฟที่ทำงานจริงแล้ว:** ตู้นิรภัยคีย์ (Android Keystore AES-256-GCM), เครือข่ายเนทีฟ (แก้ CORS/http ของ Ollama Cloud และเซิร์ฟเวอร์ในบ้าน, คีย์ไม่เข้าสู่ JavaScript), สะพาน JS↔เนทีฟแบบจำกัดต้นทาง, กู้คืนเมื่อ WebView ล่ม

## ความสามารถหลัก: อัปเกรดตัวเองจริง
หน้าเว็บอัปเดตผ่าน **OTA** (ดาวน์โหลด bundle ลงนามจาก GitHub → ตรวจ → รีบูต) ไม่ต้องลง APK ใหม่ · มีปุ่ม Build, ย้อนกลับ/ถัดไป, rollback อัตโนมัติ, เทอร์มินัลจริง, Godview, log/ตัวชี้วัด/crash · ส่วน Kotlin อัปเดตด้วย APK ที่แอปดาวน์โหลดและตรวจลายเซ็นให้ แล้ว Android ถามยืนยัน
ดูภาพรวมและข้อจำกัดที่ `android/ARCHITECTURE.md` · วิธีใช้ใน `android/GUIDE-TH.md` ข้อ 8 · เทสต์: `bash android/core-tests/run.sh` (แกน Java), `node tools/check.js` (ด่านสถิต)

## บิลด์ APK จากมือถือ
ทำตาม `android/GUIDE-TH.md` (อัปโหลด zip ไฟล์เดียว → รัน "NINO unpack zip" → ดาวน์โหลด APK จากหน้า Releases) ถ้าบิลด์แดง ให้คัดลอกข้อความ error ท้ายล็อกส่งให้ผม

### ลายเซ็นคงที่ (รีโป public ก็ทำได้)
อ่านคู่มือมือใหม่ที่ `android/GUIDE-TH.md` · สรุป: ตั้ง secret เดียว `NINO_SIGN_PASS` (ยาว 16+ ตัวอักษร) แล้วรัน workflow "NINO create signing key" ในรีโปจะมีเฉพาะไฟล์กุญแจที่เข้ารหัสแล้ว (`android/signing/nino.jks.enc`) รหัสไม่เคยปรากฏในล็อก

## หน้าจอไม่พึ่ง CDN
ตอนบิลด์ Actions สร้างไฟล์สไตล์ `tailwind.css` ใส่ในแอปและตัดการโหลดสคริปต์จาก `cdn.tailwindcss.com` ออก (ใช้ออฟไลน์ได้ และไม่มีสคริปต์ภายนอกรันในแอปที่เก็บคีย์) ถ้าสร้างไม่สำเร็จจะใช้ CDN เหมือนเดิมพร้อมเตือนในหน้า run หลังบิลด์ให้ดูหน้าจอจริง ถ้าหน้าตาเพี้ยน แจ้งผม

## ความปลอดภัย (เทียบกับเว็บบน GitHub Pages)
| ความเสี่ยง | มาตรการ |
|---|---|
| คีย์/โทเคนถูกขโมยจาก localStorage ที่ใช้ร่วมกับทุกหน้าใน github.io | ต้นทางเฉพาะของแอป · คีย์ Local AI อยู่ใน Keystore ไม่ผ่าน JS (ย้ายคีย์อื่นในเฟส 2) |
| HTML ที่ AI สร้างในพรีวิวเรียกสะพานเนทีฟ | `addWebMessageListener` จำกัด `https://appassets.androidplatform.net` + เฉพาะเฟรมหลัก (ไม่ใช้ `addJavascriptInterface` ที่เปิดให้ทุกเฟรม) |
| เครือข่ายถูกดัก/ถูกใช้โจมตีเครือข่ายภายใน | เนทีฟอนุญาต https ทุกที่ แต่ http เฉพาะเครื่องนี้/เครือข่ายในบ้าน · ไม่ตามรีไดเรกต์ |
| อ่านข้อมูลผ่าน adb backup | `allowBackup=false` |
| ดีบักจากภายนอก | เปิด WebView debugging เฉพาะบิลด์ debug |
| ไฟล์/กล้อง/ตำแหน่ง | WebView ปิดการเข้าถึงไฟล์ ปฏิเสธสิทธิ์สื่อ/ตำแหน่ง ดาวน์โหลดถูกปิด |
| APK ถูกแก้ | ลายเซ็นของคุณ · รายงาน "ตรวจสอบเว็บบ้าน" จะแสดงแฮชลายเซ็น (เฟส 2) |
ที่ยังเหลือ: เครื่องที่ root/มัลแวร์ Accessibility, PIN 4 หลักยังเช็กฝั่ง JS (ย้ายไป PBKDF2+ล็อกเอาต์เนทีฟในเฟส 2)

## แผนที่ไปสู่ภาพของ NINO
- **เฟส 2** ห้องสมุดเป็นไฟล์/ฐานข้อมูลเนทีฟ + ย้ายคีย์ทั้งหมดเข้า Keystore + PIN เนทีฟ
- **เฟส 3** หน้าจอเนทีฟ (Compose) ทีละหน้า: แชท, ห้องสมุด, ไฟล์
- **เฟส 4** ตัวแทนแยกบทบาท: *ผู้ช่วยโค้ด* (เขียน/วิเคราะห์โค้ด), *บรรณารักษ์-นักวิจัย* (จัดเอกสารในห้องสมุด, ค้นสูตร/สมการใหม่ จดลงสมุด) คุยกันผ่านตัวกลางข้อความเดียว
- **เฟส 5** วงจรพัฒนาตัวเอง: ทำแล้วใน 1.0.0 สำหรับหน้าเว็บ (OTA) และ APK (ตรวจลายเซ็นก่อนเสนอติดตั้ง Android ไม่ให้แอปเขียน APK ตัวเองทับตรงๆ นี่คือวิธีที่ปลอดภัย) ที่เหลือ: Linux userland (proot) และรีโป private
- **"จิตใจ" ของ NINO** ทำเป็นโมดูลที่ตรวจสอบได้: ไฟล์ค่านิยม/บุคลิก, ความทรงจำระยะยาว, สมุดบันทึก ที่แยกจากโค้ด แก้ได้ผ่านด่านรหัสผ่านเท่านั้น
