# คู่มือสำหรับมือใหม่: ทำ APK ของ NINO ด้วยมือถือ (รีโป public)

## 1. GitHub Actions คืออะไร (อ่านแค่นี้ก็พอ)
คือ "คอมของ GitHub ที่ยืมใช้ฟรี" เรา **ไม่ต้องมีคอม** แค่เขียนสูตรให้มันทำงานแทน: ดึงไฟล์ของเรา → ประกอบเป็น APK → วางไว้ให้ดาวน์โหลด
| คำ | แปลง่ายๆ |
|---|---|
| Workflow | ไฟล์สูตรงาน (.yml) อยู่ในโฟลเดอร์ `.github/workflows` |
| Run | การสั่งทำงาน 1 ครั้ง (✓ เขียว = สำเร็จ, ✗ แดง = พัง) |
| Step | ขั้นตอนย่อยในสูตร กดเปิดดูล็อกได้ |
| Secret | กล่องเก็บรหัสลับ ใส่แล้วดูย้อนไม่ได้ ในล็อกจะถูกปิดเป็น *** |
| Release | หน้าแจกไฟล์ มีลิงก์โหลด APK ตรงๆ (ง่ายสุดสำหรับมือถือ) |
| Artifact | ไฟล์ที่เก็บไว้ชั่วคราวในหน้า run (เป็น zip) |

## 2. ทำครั้งแรก (ครั้งเดียว)
เตรียม: แตก `nino-app-updated.zip` บนมือถือด้วยแอป Files ให้เห็นโฟลเดอร์ `nino-app-main`
1. **สร้างโฟลเดอร์สูตร** ในรีโป: Add file › Create new file › ช่องชื่อพิมพ์ `.github/workflows/อ่านก่อน.txt` (พิมพ์ `/` แล้วโฟลเดอร์ถูกสร้างเอง) › ข้างในพิมพ์อะไรก็ได้ › Commit changes
2. เข้าโฟลเดอร์ `.github/workflows` ที่เพิ่งสร้าง › Add file › Upload files › เลือก 3 ไฟล์จาก `nino-app-main/android/ci/` คือ `android.yml`, `android-keystore.yml`, `unpack-zip.yml` › Commit

> **ถ้าเคยติดตั้งรุ่นก่อนหน้าไว้แล้วและกำลังอัปเกรด** ใช้ลำดับนี้ (ไม่มี run แดงคั่น): ทำข้อ 3–5 ก่อน (อัปโหลด zip › unpack › รอ APK ✓ — workflow เดิมสร้าง APK ได้ปกติ) ติดตั้ง APK แล้ว **ค่อย** อัปโหลด `android.yml` ใหม่ทับตัวเดิม (ข้อ 2) เพราะรุ่นนี้เปลี่ยนไฟล์นี้ (แยกบิลด์เป็น `web` เร็ว ๆ กับ `apk`) เมื่ออัปโหลดแล้ว มันจะสร้าง OTA bundle ชุดแรกเอง · ต่อไปแทบไม่ต้องอัปโหลด yml อีก เพราะตรรกะย้ายไปอยู่ใน `tools/ci/*.sh` ที่อัปเดตผ่าน zip · ติดตั้งใหม่ครั้งแรก (ไม่เคยมีรีโป) ทำตามข้อ 1–6 ปกติ แดงหนึ่งรอบก่อน unpack เป็นเรื่องธรรมดา (ยังไม่มีไฟล์)  (ใช้โฟลเดอร์ `android/ci` เพราะโฟลเดอร์ที่ขึ้นต้นด้วยจุดมักถูกซ่อนในแอป Files)
3. กลับหน้าแรกของรีโป › Add file › Upload files › เลือก `nino-app-updated.zip` (ทั้งไฟล์ zip ไม่ต้องแตก) › Commit
4. แท็บ **Actions** › เลือก **NINO unpack zip** (บนมือถือถ้ามองไม่เห็นรายการ กดตัวเลือก "All workflows") › ปุ่ม **Run workflow** › Run workflow ปุ่มสีเขียว รอ ~1 นาที มันจะแตกไฟล์ใส่รีโปให้ แล้วสั่งบิลด์ต่ออัตโนมัติ
5. รอ run ชื่อ **NINO Android APK** เป็น ✓ เขียว (~5–10 นาที)
6. หน้าแรกของรีโป › Releases (ขวาหรือเมนู) › **NINO ล่าสุด** › แตะ `NINO.apk` เพื่อโหลด › เปิดไฟล์ติดตั้ง (ต้องอนุญาต "ติดตั้งจากแหล่งนี้" ครั้งแรก)

## 3. ตั้งกุญแจลงนาม (ควรทำก่อนใช้งานจริง)
> **รหัสผ่านต้องยาว 16 ตัวขึ้นไป (ไม่ลดเป็น 8)** เพราะไฟล์กุญแจที่เข้ารหัสแล้วอยู่ในรีโปสาธารณะ ใครก็ดาวน์โหลดไปลองเดารหัสได้ที่บ้านโดยไม่ถูกจับ รหัสยิ่งสั้นยิ่งเดาได้ จึงไม่มีทางลดให้สั้นลง ถ้าใส่ `NINOMINI` (8 ตัว) ขั้นตอนสร้างกุญแจจะหยุดและแจ้งว่าสั้นเกินไป ซึ่งเป็นพฤติกรรมที่ถูกต้อง
> **อย่าส่งรหัสผ่านให้ใครหรือ AI ทางแชท** ใส่รหัสได้เฉพาะในหน้า Secret ของ GitHub เท่านั้น
> วิธีตั้งรหัสที่จำง่ายบนมือถือ: ใช้ตัวสร้างรหัสของ Google Password Manager หรือของ Password Manager ที่มี เลือกสร้างรหัส 20 ตัว แล้วคัดลอกไปวางในช่อง Secret ทันที จากนั้นบันทึกรหัสไว้ในตัวจัดการรหัสผ่านของคุณ
ถ้าไม่ตั้ง APK จะลงนามด้วยกุญแจชั่วคราวที่เปลี่ยนทุกครั้ง ทำให้ **ติดตั้งทับไม่ได้ ต้องถอนก่อนและข้อมูลในแอปหาย**
วิธีนี้ปลอดภัยบนรีโป public: รหัสอยู่ใน Secret เท่านั้น ในรีโปมีแค่ไฟล์กุญแจที่ **เข้ารหัสแล้ว**
1. คิด **รหัสผ่านยาว 16 ตัวขึ้นไป** ที่เดายาก เช่นคำสุ่ม 5 คำต่อกัน (ห้ามใช้ตัวอย่างในคู่มือ) แล้ว **จดเก็บไว้ที่อื่น** (ถ้าลืม ต้องสร้างกุญแจใหม่และถอนแอปเดิม)
2. Settings (ถ้าไม่เห็นแท็บ กดเมนูลูกศรลงแล้วเลือก Settings) › Security › **Secrets and variables › Actions** › แท็บ Secrets › **New repository secret** › Name: `NINO_SIGN_PASS` › Secret: รหัสของคุณ › Add secret
3. Actions › **NINO create signing key (run once)** › Run workflow (รอ ~2 นาที มันสร้างกุญแจ เข้ารหัส และ commit ไฟล์ `android/signing/nino.jks.enc`)
4. Actions › NINO Android APK › Run workflow อีกครั้ง ต่อไป APK จะลงนามด้วยกุญแจเดียวตลอด ติดตั้งทับได้ ข้อมูลไม่หาย
ห้ามสร้างกุญแจซ้ำ (ระบบกันไว้ให้แล้ว)

## 4. อัปเดตทุกครั้งต่อไป
อัปโหลดไฟล์ zip ใหม่ที่หน้าแรกของรีโป › Actions › NINO unpack zip › Run workflow › รอ ✓ › โหลด APK ใหม่จาก Releases
(ถ้า zip ใหม่มีไฟล์ workflow ที่เปลี่ยน ระบบจะแจ้งในหน้า run ให้ไปอัปโหลดไฟล์จาก `android/ci` เองตามข้อ 2 เพราะ GitHub ไม่ให้ระบบอัตโนมัติแก้ไฟล์สูตรเอง)

## 5. ถ้า run เป็น ✗ แดง (ปกติของมือใหม่ ไม่ต้องตกใจ)
1. Actions › แตะ run ที่แดง › แตะขั้นตอนที่มีเครื่องหมาย ✗
2. เลื่อนไปท้ายสุดของข้อความ คัดลอก 30–40 บรรทัดสุดท้าย (มีคำว่า `error:` หรือ `e: ` หรือ `FAILED`)
3. ส่งให้ผมในแชท ผมคอมไพล์เองไม่ได้ ต้องอาศัยข้อความนี้ในการแก้

## 6. ปัญหาที่เจอบ่อย
| อาการ | สาเหตุ/วิธีแก้ |
|---|---|
| ไม่มีปุ่ม Run workflow | ไฟล์ .yml ต้องอยู่ที่ `.github/workflows/` และอยู่ branch หลัก (main) · ลองรีเฟรชหน้า |
| NINO unpack zip แดง: ไม่พบ .zip | อัปโหลด zip ไว้หน้าแรกของรีโป (ไม่ใช่ในโฟลเดอร์ย่อย) |
| แดงที่ "Restore signing key": รหัสไม่ตรง | ค่า `NINO_SIGN_PASS` ไม่ตรงกับตอนสร้างกุญแจ แก้ Secret ให้ตรง |
| ติดตั้งแล้วขึ้น "App not installed" | ลายเซ็นไม่ตรงกับแอปที่ลงไว้ ถอนแอปเก่าก่อน (ข้อมูลในแอปหาย) แล้วตั้งกุญแจตามข้อ 3 กันซ้ำ |
| Run ขึ้นว่าไม่มีสิทธิ์เขียน (403) | Settings › Actions › General › Workflow permissions เลือก Read and write |
| Static gate แดง พร้อมข้อความ `Cannot find module ... tools/check.js` | รีโปยังไม่มีโค้ด NINO เพราะยังไม่ได้แตก zip (หรือรัน workflow ก่อนแตกไฟล์) · อัปโหลด NINO.zip ที่หน้าแรกของรีโป › รัน **NINO unpack zip** ให้ ✓ ก่อน แล้วค่อยรัน **NINO Android APK** · การอัปโหลด zip อย่างเดียวจะไม่เรียก workflow แล้ว |

## 7. รีโป public ปลอดภัยแค่ไหน
- **ใครก็เห็นได้:** โค้ดทั้งหมด, APK, ล็อกของ run (ล็อกปิดค่า Secret เป็น ***)
- **ไม่ควรอยู่ในรีโปเลย:** คีย์ API ของ Gemini/Ollama, โทเคน GitHub — ใส่ในแอปเท่านั้น (หน้า Local AI ใน `>_` เก็บคีย์ในตู้นิรภัยของเครื่อง)
- รหัส `NINO_SIGN_PASS` ต้องยาวและเดายาก เพราะไฟล์กุญแจที่เข้ารหัสอยู่ในที่สาธารณะ ความปลอดภัยของมันคือความยาวของรหัสนี้

## 8. ใช้ Console: Build, ย้อนกลับ, เทอร์มินัล, Godview (แอป APK 1.0.0 ขึ้นไป)
เปิด: `>_` › **Console** มี 4 แท็บ

**Versions — ปุ่ม Build (ใช้บ่อยสุด)**
1. สั่งงาน NINO ตามปกติ (แก้ไฟล์ผ่าน gh_* ได้เหมือนเดิม)
2. เปิด Console › Versions › กด **Build & รีบูตทั้งแอป** ถ้า NINO ยังทำงานอยู่ มันจะ "รอ" ให้เสร็จก่อนเอง
3. ดูรายการขั้นตอนวิ่ง: จับภาพก่อน → commit → รอ GitHub สร้างเวอร์ชันใหม่ (~1 นาที) → ดาวน์โหลด+ตรวจลายเซ็น → **แอปรีบูต** → จับภาพหลัง → เทียบ
4. เลื่อนดูผลเทียบ ก่อน/หลัง แล้วเลือก **ใช้ต่อ** หรือ **ย้อนกลับ**
- **ย้อนกลับ / ถัดไป ** ไปเวอร์ชันที่เก็บไว้ในเครื่อง (12 รุ่นล่าสุด) · "ใช้เวอร์ชันนี้" เลือกเองได้ · ปักหมุดไม่ให้ถูกลบ
- "ดูเวอร์ชันเก่าบน GitHub" ดึงรุ่นที่เคยทำแต่ไม่ได้อยู่ในเครื่องมาเก็บ
- ถ้าเวอร์ชันใหม่เปิดไม่ขึ้น แอป **ถอยกลับเอง** ภายใน 30 วินาที และแจ้งเหตุผล (ไม่มีทางถูกล็อกนอกแอป)
- Build จะไม่แตะเวอร์ชันที่ใช้อยู่ถ้า CI แดง (แสดงลิงก์ให้เปิดดู)
- NINO สั่ง Build เองไม่ได้ มันแค่ **ขอ** แล้วคุณกดยืนยัน (เปิดโหมดอัตโนมัติได้ในหน้าเดียวกัน ปกติปิดไว้)

**เมื่อไรต้อง "ติดตั้ง APK"**: เฉพาะเมื่อ NINO แก้ไฟล์ใต้ `android/` (Kotlin/Java/manifest) Build จะรอ APK ให้แล้วถามก่อนติดตั้ง จากนั้น Android จะขอให้กดยืนยันอีกครั้งและแอปรีสตาร์ต ครั้งแรกต้องเปิด "ติดตั้งแอปที่ไม่รู้จัก" ให้ NINO (แอปพาไปหน้านั้นให้เอง) ลายเซ็น APK ใหม่ต้องตรงกับที่ลงอยู่ จึง **ต้องตั้งกุญแจลงนามตามข้อ 3 ก่อน**

**Terminal** เชลล์จริงของเครื่อง (ภายในพื้นที่ของแอป ไม่ใช่ root) ครั้งแรกจะมีกล่องถามอนุญาต · พิมพ์ `help` ดูคำสั่งในตัว `nino ...` · ไม่มี vi/top และ Ctrl-C ใช้รีสตาร์ตเชลล์ · ยังไม่ใช่ Linux เต็มรูป (ดู `ARCHITECTURE.md` ข้อ 11)

**Godview** กด จับภาพก่อนแก้ แล้วจับอีกครั้งหลังแก้ แตะภาพแรก=ก่อน ภาพที่สอง=หลัง › เทียบ เห็นภาพคู่ + heatmap ส่วนที่เปลี่ยน + รายการปัญหาใหม่ (ล้นจอ, ปุ่มเล็กเกิน, รูปเสีย ฯลฯ) · ปุ่ม "ส่งภาพให้ AI" แนบภาพเข้าข้อความถัดไป

**Logs** log เนทีฟ + หน้าเว็บ, ตัวชี้วัด, รายงาน crash ครั้งก่อน · ปุ่ม **คัดลอกรายงานวินิจฉัย** แล้ววางให้ AI/ส่งให้ผมได้ในครั้งเดียว

## 9. ปัญหาที่เจอบ่อย
| อาการ | สาเหตุ/วิธีแก้ |
|---|---|
| Build ค้างที่ "รอ GitHub สร้างเวอร์ชันใหม่" นาน | เปิด Actions ดู run **NINO Android APK** ว่ามี job `web` สีเขียวไหม · ถ้าแดงที่ `check` อ่านข้อความท้ายล็อกส่งให้ผม · รอสูงสุด 15 นาทีแล้วแอปแจ้งเอง |
| "ลายเซ็นของ bundle ไม่ถูกต้อง" | APK ที่ลงอยู่ลงนามด้วยกุญแจอื่นกับตอนที่ CI ลงนาม bundle → ตั้งกุญแจตามข้อ 3 แล้วลง APK ใหม่ครั้งเดียว |
| "ต้องอัปเดต APK ก่อน" | เวอร์ชันเว็บใหม่ใช้คำสั่งเนทีฟที่ APK เก่าไม่มี → ติดตั้ง APK ล่าสุด (Console › Versions › ส่วนเนทีฟ) |
| งาน `Android APK` แดงใน Actions | เปิด run นั้น เลื่อนลงหัวข้อ Summary จะมีกล่อง "Android APK ล้ม" แสดงท้ายล็อก SDK/Gradle · ถ้าเห็น `licences have not been accepted` หรือ `Could not resolve` ให้กด Re-run failed jobs ก่อน 1 ครั้ง · `OTA web bundle` ที่เขียวพอสำหรับอัปเดตหน้าเว็บ (APK ต้องสร้างใหม่เมื่อแก้ไฟล์ใต้ `android/` เท่านั้น) |
| "ยังไม่ได้ตั้งค่า GitHub repo" | ตั้งค่า GitHub (owner/repo/token) ก่อน |
| หลังติดตั้ง APK ใหม่ หน้าจอกลับไปเป็นเวอร์ชันเดิมของ APK | ตั้งใจ: APK ใหม่ใช้หน้าเว็บที่ติดมากับมันก่อน แล้วกด "ตรวจเวอร์ชันใหม่" ถ้ามี bundle ที่ใหม่กว่า |

## 10. ตรวจก่อนติดตั้งทุกครั้ง (ทำได้ด้วยมือถือ)
1. **กุญแจ:** เปิด run ของ NINO Android APK › Summary › หัวข้อ "APK ที่สร้างรอบนี้" ต้องไม่มีข้อความ "debug key ชั่วคราว" และค่า SHA-256 ต้องเท่ากับรอบก่อนหน้าทุกครั้ง ถ้าเปลี่ยนแปลงเองแปลว่ากุญแจเปลี่ยน ติดตั้งทับไม่ได้
2. **ใหม่ที่สุด:** Releases › NINO ล่าสุด › หัวเรื่องบอกหมายเลข run และ commit ต้องตรงกับ run สีเขียวล่าสุดในแท็บ Actions ถ้าไม่ตรง แปลว่า run ล่าสุดล้มเหลวและไฟล์ที่เห็นเป็นของรอบเก่า
3. **เวอร์ชัน:** ระบบจะไม่ให้ versionCode ลดลง ถ้ามีการปรับเลขให้จะขึ้นในข้อความ notice ของ run
4. **หน้าเว็บกับ APK:** ถ้าหน้าเว็บต้องการ APK ใหม่ ระบบจะสร้าง APK ให้เอง (ดูข้อความ "bridge" ในล็อกของด่านแผน) จึงไม่ต้องรอ APK ที่ไม่มีวันมา
5. **ไลบรารี native:** ถ้า Summary แจ้งว่ามีไลบรารีนอก arm64-v8a รอบนั้นจะล้มทันที (ป้องกัน APK ที่ติดตั้งไม่ได้บนบางเครื่อง)
6. **SDK:** ถ้า step "Ensure Android SDK" แดงพร้อมข้อความ "ไม่มี platforms/android-34" เป็นปัญหาของเครื่องบิลด์ ให้กด Re-run failed jobs หนึ่งครั้ง ถ้ายังแดงให้ส่งข้อความนั้นมาให้ผม

## 11. เลขเวอร์ชันของแอป
เลขที่แอปแสดงคือค่า `NINO_VERSION` ใน `version.js` (ตอนนี้ 1.0.0) APK ใช้เลขเดียวกันนี้เป็น versionName โดยอัตโนมัติ จึงแก้ที่ `version.js` ที่เดียวพอ
