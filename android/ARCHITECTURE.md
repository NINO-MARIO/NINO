# NINO Native Platform — สถาปัตยกรรม (v1.0.0)

เอกสารนี้อธิบายว่า NINO เป็นแอปเนทีฟแค่ไหน อัปเกรดตัวเองได้อย่างไร และอะไรคือข้อจำกัดจริง อ่านคู่กับ `GUIDE-TH.md` (วิธีใช้) และ `README.md` (ความปลอดภัย)

## 1. คำตอบสั้น: ตอนนี้เป็นเนทีฟหรือยัง

| เรื่อง | ก่อนการปรับปรุง | ปัจจุบัน |
|---|---|---|
| โครงแอป | Kotlin + WebView ที่ฝังไฟล์เว็บไว้ใน APK ตอนบิลด์ | เหมือนเดิม + **ที่เก็บเวอร์ชันบนเครื่อง** (`filesDir/ota/`) |
| หน้าเว็บอัปเดตโดยไม่ลง APK ใหม่ | ไม่ได้ (commit แล้วแอปไม่เปลี่ยน) | **ได้** ดาวน์โหลด bundle ที่ลงนามจาก GitHub ตรวจแล้วรีบูต |
| ตรวจเวอร์ชันใหม่ | อ่าน `./version.js` ซึ่งใน APK คือไฟล์ที่ฝังมาเอง จึง **ไม่มีทางเห็นเวอร์ชันใหม่** | อ่านตัวชี้ `web-latest` จาก GitHub ผ่านเนทีฟ |
| ย้อนกลับ/ถัดไป | ไม่มี | มี (เก็บ 12 เวอร์ชัน) + rollback อัตโนมัติถ้าเวอร์ชันใหม่เปิดไม่ผ่าน |
| เทอร์มินัล | เชลล์จำลองใน JS | เชลล์จริงของเครื่อง (`/system/bin/sh`) |
| ดูตัวเองแบบก่อน/หลัง | ไม่มี | Godview: ภาพหน้าจอจริง + ตรวจโครงสร้าง + diff |
| สังเกตการณ์ | console.log | log เนทีฟแบบหมุนไฟล์ + ตัวชี้วัด + รายงาน crash + รายงานวินิจฉัย |
| อัปเดตส่วนเนทีฟ (Kotlin) | ลงมือเอง | ดาวน์โหลด APK + ตรวจ sha256 + **ตรวจว่าลายเซ็นตรงกับแอปที่ลงอยู่** แล้วส่งให้ตัวติดตั้งของ Android |

ที่ **ยังไม่ใช่**: Linux userland เต็มรูป (ดูข้อ 11) และ UI เนทีฟทั้งหมด (หน้าจอยังเป็นเว็บใน WebView ตามแผนเฟส 3)

## 2. สามชั้น

```
┌────────────────────────── WebView (https://appassets.androidplatform.net/app/...) ───────────────────────────┐
│  หน้าเว็บ (js/*.js)  ← ชั้นที่ NINO แก้ได้เร็วที่สุด อัปเกรดผ่าน OTA ภายใน ~1 นาที                         │
│  js/ota.js · nino-sys.js (Build) · term.js · godview.js · console-ui.js · obs.js                              │
└───────────────────────────────────────── สะพาน addWebMessageListener (จำกัดต้นทาง + เฟรมหลัก) ───────────────┘
┌────────────────────────── Kotlin (app.nino) ── ชั้นบางๆ ที่แตะ Android ─────────────────────────────────────┐
│  MainActivity · NativeBridge · LiveAssets (เสิร์ฟ /app/ จาก bundle) · Consent · Snap · ApkUpdater · NinoApp  │
└───────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
┌────────────────────────── Java ล้วน (app.nino.core) ── ไม่มี import android.* เทสต์บน JVM ได้จริง ──────────┐
│  BundleStore · OtaCore · Fetcher · HostPolicy · Trust · ZipSafe · RingLog · Shell · MiniJson                  │
└───────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

เหตุผลที่แกนเป็น Java ล้วน: ตรรกะที่ผิดแล้วเสียหายหนัก (ตรวจลายเซ็น, แตก zip, rollback) ต้องทดสอบได้จริงทุกครั้งที่ push โดยไม่ต้องมี Android SDK ส่วน Kotlin เหลือเป็นกาวบางๆ ที่ตรวจด้วย `tools/check.js` (ดูข้อ 12)

## 3. ตัวไหนรับงานแก้อะไร

| สิ่งที่แก้ | ต้องบิลด์อะไร | ใช้เวลา | ผู้ใช้ต้องทำ |
|---|---|---|---|
| `js/*.js`, `index.html`, `skills/**`, CSS | **web bundle** (OTA) | ~1 นาที | กดปุ่ม Build ใน Console (แอปดาวน์โหลดและรีบูตเอง) |
| `android/app/**` (Kotlin/Java/manifest/gradle) | **APK** | ~5–8 นาที | กด "ติดตั้ง APK" แล้วยืนยันในหน้าต่างของ Android |
| ทั้งสองอย่างใน commit เดียว | ทั้งคู่ | — | Build จัดลำดับให้ |
| `.github/workflows/*.yml` | — | — | อัปโหลดมือ (GitHub ไม่ให้บอตแก้) ตรรกะส่วนใหญ่ย้ายไป `tools/ci/*.sh` จึงต้องแตะ yml น้อยมาก |

`push` ที่แก้เฉพาะหน้าเว็บ **ไม่** บิลด์ APK (ประหยัดเวลา) APK บิลด์เมื่อแตะ `android/app|build.gradle|settings.gradle|gradle` หรือสั่งมือ (`target` = both/web/apk)

## 4. โปรโตคอล OTA

รีลีส `web-<sha7>` (immutable, ลบเองเมื่อเกิน 30 รายการ) มี 3 ไฟล์:

- `web-bundle.zip` — ไฟล์เว็บทั้งหมด `index.html` ที่รูท, ไม่มี `./` นำหน้า, ไม่มี `.apk/.dex/.so/.jar/.sh/.exe`
- `bundle.json` — `{schema:1, id, version, commit, message, builtAt, run, minBridge, zip:{name,size,sha256}}`
- `bundle.json.sig` — RSA-SHA256 ของ `bundle.json` ด้วย **กุญแจเดียวกับที่ลงนาม APK** (`tools/ci/sign-file.sh`)

`web-latest/latest.json` คือตัวชี้ `{tag, run, ...}` (ไม่ลงนามโดยตั้งใจ มันแค่ชี้ไปรีลีสที่ลงนามแล้ว และขยับไปข้างหน้าเท่านั้น)

ลำดับที่แอปตรวจ (`OtaCore.install`) ล้มข้อไหนหยุดทันทีและไม่เขียนอะไรลงดิสก์ที่ใช้งานอยู่:

1. tag ต้องตรง `^web-[A-Za-z0-9._-]+$` · ทุกคำขอ/ทุก redirect ต้องเป็น https ไปยังโฮสต์ในรายการ GitHub เท่านั้น (`HostPolicy`) · โทเคนส่งเฉพาะ github.com/api.github.com ไม่ส่งไป CDN
2. `bundle.json` ≤ 64 KB · ลายเซ็นตรงกับใบรับรองของแอปเอง (บังคับในบิลด์ที่ลงนาม; บิลด์ debug ผ่อนได้และแสดงเป็น "unsigned")
3. schema/id/ชื่อ zip/ขนาด (≤ 80 MB)/sha256 ผ่านรูปแบบ · `minBridge` ≤ bridge ของแอป ไม่งั้นต้องอัปเดต APK ก่อน
4. ไม่ย้อนเวอร์ชันเงียบๆ: `run` ต่ำกว่าที่รันอยู่ถูกปฏิเสธ เว้นแต่ผู้ใช้เลือกเอง (ย้อนจากประวัติ)
5. ดาวน์โหลดแบบสตรีมพร้อมเพดานขนาด → ขนาดตรง → sha256 ตรง (ห้ามผ่านแม้ลายเซ็นผ่านแล้ว)
6. แตก zip (`ZipSafe`): ปฏิเสธ `..`, path เริ่มด้วย `/`, `\`, `:`, นามสกุลอันตราย, ไฟล์เกิน 64 MB, รวมเกิน 200 MB, เกิน 4000 ไฟล์ · ต้องมี `index.html` ที่รูท · แตกเข้าโฟลเดอร์ชั่วคราวแล้วย้ายเข้าที่ (atomic)

`NINO_REPO` ถูกฝังใน APK ตอนบิลด์ (`-PninoRepo`) แอปอัปเดตจากรีโปนี้เท่านั้น ไม่เชื่อรีโปที่หน้าเว็บส่งมา

## 5. ที่เก็บเวอร์ชันและ rollback (`BundleStore`)

เก็บที่ `filesDir/ota/` — `bundles/<id>/` กับ `state.properties` (เขียนแบบ tmp → rename อะตอมมิก, ไฟล์เสีย → เริ่มใหม่ที่ builtin ไม่ล็อกแอป)

```
builtin ──activate──X (pending) ──หน้าเว็บเรียก ota.healthy──X (healthy, lastGood = X)
                          │
                          ├─ เปิดไม่ผ่านเกิน 2 ครั้ง / ไม่ส่งสัญญาณใน 30 วินาที / WebView ล้ม / main frame โหลดไม่ได้ / native crash
                          ▼
                    rollback → prev (หรือ lastGood หรือ builtin)   X ถูกติดธง bad (ข้ามเวลากดถัดไป)
```

- ผู้ใช้ย้อนกลับ/ถัดไป/เลือกเวอร์ชันเองได้เสมอ `bad` ไม่ได้ห้าม แค่ข้ามตอนกด ถัดไป/ย้อนกลับ
- หน้าเว็บยืนยันสุขภาพเมื่อ `dispatchTool, ninoGH, ninoLib, renderMessages` มีครบ และ error ช่วงบูต ≤ 3 (`js/ota.js`) · ถ้าไม่ผ่านจะสั่ง `ota.fail` เอง · ถ้า JS พังจนเรียกอะไรไม่ได้ **watchdog ฝั่ง Kotlin** ถอยให้ ผู้ใช้ไม่มีทางถูกล็อกนอกแอปด้วยหน้าเว็บที่พัง
- APK ใหม่ (versionCode เปลี่ยน) → กลับไปใช้ builtin ของ APK นั้น (เก็บประวัติไว้) ไม่งั้น bundle เก่าจะบังหน้าเว็บที่ใหม่กว่า
- เก็บสูงสุด 12 เวอร์ชัน ตัดตัวเก่าสุดที่ไม่ปักหมุด/ไม่ใช่ตัวที่ใช้อยู่/ตัวก่อนหน้า/lastGood

## 6. ปุ่ม Build (`js/nino-sys.js`)

กดแล้ว: **รอ NINO ทำงานเสร็จ** (สถานะ busy ต้องนิ่ง 2 วินาที) → จับภาพ "ก่อน" → commit ไฟล์ที่ค้าง (ถ้าแตะไฟล์ป้องกัน จะถามยืนยันตามระบบเดิม) → รอ CI เผยแพร่ `web-<sha7>` (ดูสถานะรันจาก GitHub และหยุดทันทีพร้อมลิงก์ถ้าแดง) → ดาวน์โหลด+ตรวจ → รีบูตทั้งแอป → หลังบูต จับภาพ "หลัง", เทียบ, รายงาน และให้เลือก ใช้ต่อ / ย้อนกลับ

- งานที่แตะ `android/` → รอ `apk.json` ของ commit นั้น (หรือใหม่กว่า) แล้วขอให้ผู้ใช้ยืนยันติดตั้ง APK
- AI สั่ง `app_build` ได้แค่ **ขอ** — ต้องให้คนกดยืนยันที่ Console (หรือเปิดโหมดอัตโนมัติเอง ปกติปิด)
- ยกเลิกได้ระหว่างรอ; ล้มกลางทาง → ไม่แตะเวอร์ชันที่รันอยู่

## 7. เทอร์มินัล

เชลล์จริงของ Android (`/system/bin/sh -i`, stderr รวม stdout, `HOME=filesDir/home`) ผ่านท่อ stdin/stdout ไม่มี PTY

- เปิดครั้งแรกต่อโปรเซส → **กล่องยืนยันเนทีฟ** (JS กดเองไม่ได้)
- คำสั่งที่ AI รัน (`term_exec`) ต้องกดอนุญาตทุกครั้ง หรือ "ทั้งเซสชัน" · คำสั่งทำลายล้างที่เห็นชัด (`rm -rf /`, `pm uninstall`, `reboot`, `su`, fork bomb ฯลฯ) ถูกปฏิเสธก่อนถึงกล่อง (ชั้นเสริม ไม่ใช่ sandbox — sandbox จริงคือสิทธิ์ของแอป)
- เซสชันอยู่รอดตอน WebView รีโหลด (ต่อกลับด้วย backlog 64 KB) · timeout/เพดานผลลัพธ์ในโหมด exec
- **ไม่รองรับ** vi/top/โปรแกรมเต็มจอ และ Ctrl-C จริง (ปุ่ม Ctrl-C รีสตาร์ตเชลล์) เพราะไม่มี PTY

## 8. Godview

`snap.take` ใช้ `PixelCopy` (API 26+) จับพิกเซลจริงของหน้าจอ ย่อเป็น JPEG ≤ 720px เก็บ 60 ภาพล่าสุด เสิร์ฟที่ `/snaps/<id>.jpg` (ต้นทางเดียวกัน จึงอ่านพิกเซลด้วย canvas ได้) ซ่อน Console ชั่วคราวระหว่างจับ

ตรวจโครงสร้างหน้า: เลื่อนข้างทั้งหน้า, element เกินขอบจอ, ปุ่มเล็กกว่า 28px, ข้อความถูกตัด, รูปเสีย, element fixed ที่หลุดจอบางส่วน, error ใน 60 วินาที · เปรียบเทียบ: เปอร์เซ็นต์พิกเซลที่เปลี่ยน + ตารางความร้อน 8×14 + heatmap + diff ข้อความ/ปัญหา "ใหม่" (ปัญหาเดิมไม่ถูกนับซ้ำ) · มีสรุปเป็นข้อความให้ AI อ่านต่อได้ และแนบภาพเข้าแชทได้สำหรับโมเดลที่มองภาพได้

|---|---|

| ตัวนับ | `boot.count, ota.installs, ota.rollbacks, webview.render_gone, js.errors, net.requests/errors, term.exec, log.errors …` |

| crash | handler จับ exception ทุกเธรด → `crash-<ts>.txt` (stack + ตัวนับ + log 120 บรรทัด) ถ้ากำลังทดลอง bundle ใหม่จะ rollback ให้ด้วย · แท็บ Logs แจ้งตอนเปิดครั้งถัดไป |
| รายงานวินิจฉัยฉบับเดียว | `nino diag` / ปุ่มคัดลอก / เครื่องมือ `app_diag` |

## 10. โมเดลความเชื่อถือ

| ภัย | มาตรการ |
|---|---|
| ใครแอบวาง bundle ปลอมใน GitHub | ต้องลงนามด้วยกุญแจ APK (ไม่อยู่ในรีโป อยู่ใน Secret) · บังคับในบิลด์ลงนาม |
| bundle ถูกแก้ระหว่างทาง/ดาวน์โหลดไม่ครบ | https + allowlist + sha256 + ขนาด |
| zip ประสงค์ร้าย (zip-slip, bomb) | `ZipSafe` (มีเทสต์ mutation: ถอดการป้องกันแล้วเทสต์ล้ม) |
| ถูกบังคับให้ถอยเวอร์ชัน | `run` ต้องไม่ต่ำกว่าเดิมเว้นแต่ผู้ใช้เลือก |
| APK ใหม่ที่ลงนามด้วยกุญแจอื่น | แอปเทียบใบรับรองของไฟล์ที่ดาวน์โหลดกับของแอปที่ติดตั้ง ไม่ตรง = ลบทิ้ง |
| JS ที่เสียหายสั่งเชลล์เอง | กล่องยืนยันเนทีฟ + ตัวกรองคำสั่ง + เชลล์อยู่ใน sandbox ของแอป |
| บั๊กใน bundle ใหม่ทำให้ใช้ไม่ได้ | health check + watchdog + rollback อัตโนมัติ |

ที่ **ไม่ได้แก้** (มีมาตั้งแต่ก่อนการปรับปรุง): `authVault` ของ `http` ส่งคีย์ที่เก็บในตู้นิรภัยเป็น Bearer ไปยัง URL ใดก็ได้ที่ผ่านนโยบาย ถ้า JS ถูกยึดมันขโมยคีย์ Local AI ได้ OTA ที่ลงนามทำให้ JS น่าเชื่อถือเท่า APK แต่ถ้าจะให้แน่นขึ้นควรผูกคีย์กับโฮสต์ปลายทางตอนบันทึก (ทำได้ในเฟส 2)

## 11. ข้อจำกัดที่ยังมีจริง

- **ไม่มี Linux userland / พรีบิวต์เครื่องมือ**: Android 10+ ห้ามรันไบนารีจากโฟลเดอร์ข้อมูลของแอป (W^X) การมี "fiuxlinux" ต้องฝัง proot + rootfs เป็นไลบรารีในแอป (jniLibs) ซึ่งยังไม่ทำ เทอร์มินัลตอนนี้ใช้ toybox ของระบบ (`ls cat grep sed ping wget …` แล้วแต่รุ่นเครื่อง)
- APK ใหม่ **ต้องให้ผู้ใช้กดยืนยัน** (Android บังคับ) และต้องเปิด "ติดตั้งแอปที่ไม่รู้จัก" ให้ NINO หนึ่งครั้ง
- ย้อนกลับ **ส่วนเนทีฟ** ไม่ได้ผ่านแอป (Android ไม่ให้ downgrade) ให้ revert commit แล้วบิลด์ใหม่ (versionCode เพิ่มต่อเนื่องจากเลข run) · สำเนา APK เก่า 10 รุ่นล่าสุดอยู่ใน Releases `apk-<run>`
- OTA ใช้ได้กับรีโป **public** (ดาวน์โหลดจาก `releases/download`) · รีโป private ต้องเปลี่ยนไปใช้ API asset ซึ่งยังไม่ทำ
- หน้าจอ Godview ที่ครอบด้วย Surface พิเศษ (วิดีโอ/DRM) อาจเป็นสีดำตามข้อจำกัด `PixelCopy`
- แอปเดิมมีปุ่มที่เล็กกว่า 28px หลายจุด (เช่น //รีเซ็ตบนแถบบน) Godview รายงานไว้ ยังไม่ได้ปรับ UI

## 13. เพิ่มคำสั่งเนทีฟใหม่ (เช็กลิสต์)

1. เพิ่มสาขา `"ชื่อ.op" ->` ใน `NativeBridge.dispatch` · พารามิเตอร์ห้ามชื่อ `id`/`op` (ชนกับโปรโตคอล)
2. เรียกจากเว็บผ่าน `ninoNative.call('ชื่อ.op', {...}, onEvent)`
3. ถ้าเว็บเริ่มพึ่งคำสั่งใหม่ → เพิ่ม `BRIDGE_API` ใน `NativeBridge.kt` **และ** `NINO_BRIDGE_API`/`bridge:` ใน `version.js`/`js/native-bridge.js` (bundle ที่ต้องการ bridge สูงกว่าจะไม่ลงใน APK เก่า)
4. เพิ่มกรณีใน `tools/test/native-mock.js` แล้วเขียนเทสต์เบราว์เซอร์
5. `node tools/check.js` ต้องเขียว (มันจะบ่นถ้า op/พารามิเตอร์ไม่ตรงกัน)


## 14. ฉากและแพ็ก (Gen 2)
สื่อหนักไม่อยู่ในบันเดิล OTA/APK (`tools/ci/prepare-web.sh` ตัด `packs/` ออก) แอปโหลดจาก `packs/manifest.json` ของรีโปที่ตั้งไว้ (เว็บ = ./packs/ · APK = raw.githubusercontent.com ตามค่าปุ่ม GH) เก็บใน Cache Storage ชื่อ `nino-packs` ตรวจ sha256 ทีละไฟล์ ใช้ออฟไลน์ได้เมื่อโหลดครบ · เวอร์ชันแพ็กคือแฮชของเนื้อไฟล์ จึงแพตช์เฉพาะไฟล์ที่เปลี่ยนโดยไม่ต้องอัปเดตแอป · ยังไม่มีคำสั่งเนทีฟสำหรับเก็บแพ็ก (ใช้ Cache Storage ของ WebView) ถ้าต้องการพื้นที่เก็บใหญ่ขึ้นให้เพิ่ม op ใน NativeBridge ตามข้อ 13
