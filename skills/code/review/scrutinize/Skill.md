# scrutinize
ก่อน commit ที่แตะไฟล์ [ล็อก] หรือแก้เกิน 3 ไฟล์ และเมื่อผู้ใช้ขอให้ช่วยดู: ไล่เส้นทางโค้ดจริงแบบคนนอกว่าทำตามที่อ้างไหม
## ท่าที
- คนนอก: อ่านเย็นๆ ลืมว่าใครเขียนและเขาเชื่ออะไร · ตรวจปลายถึงปลาย ไม่ใช่แค่ใน diff (บั๊กซ่อนที่รอยต่อ) · กระชับ ลงมือทำได้ ทุกข้อมีเหตุผลและหลักฐาน
## ขั้นตอน (ตามลำดับ ห้ามข้าม)
1. เจตนา — เขียนเป้าหมายหนึ่งประโยคด้วยคำตัวเอง เขียนไม่ได้ = งานกำกวม บอกแล้วหยุด · แล้วถามหนึ่งครั้งเสมอ: มีทางที่ง่ายกว่า/เล็กกว่า/สวยกว่าไหม (ไม่ทำอะไร? ใช้ของที่มีอยู่ใน NOW.md/แผนที่ไฟล์? แก้ที่ชั้นอื่น?) ถ้ามีให้ระบุพร้อมเหตุผลก่อนรีวิวรายบรรทัด นี่คือของมีค่าที่สุด
2. ไล่เส้นทาง — ทุกพฤติกรรมที่อ้าง ไล่จริง: จุดเข้า → ผู้เรียก → กิ่งที่เดิน → state ที่เปลี่ยน → ผลลัพธ์/ผลข้างเคียง รวมโค้ดที่ไม่ได้แก้รอบๆ diff · ใช้ gh_diff เป็นจุดเริ่ม แล้ว gh_grep หาผู้เรียก gh_read_func/gh_outline อ่านเส้นทาง · จดทุกที่ที่ "ประหลาดใจ" นั่นคือสัญญาณ
3. ยืนยัน — แต่ละข้ออ้าง: "อ้างว่า X · เส้นทาง A→B→C · ที่ C พบ … · สรุป: จริง/ไม่จริง" · อินพุตหรือสถานะอะไรทำให้พัง (ว่าง/null/ไทย/ใหญ่มาก/เรียกพร้อมกัน/ล้มกลางทาง/ลำดับ script) · เงียบๆ เปลี่ยนอะไร (ประสิทธิภาพ ความหมายของ error สัญญากับผู้เรียกอื่น รูปแบบข้อมูลใน localStorage) · เทสต์ครอบเส้นทางที่ไล่จริงไหม หรือผ่านเพราะ mock ซ่อนบั๊ก
   - NINO เพิ่ม: ชื่อ function/const ซ้ำข้ามไฟล์ไหม (sh run skills/code/debug/debug-loop/scripts/find_dup_globals.js) · ลำดับ script ใน index.html · แตะไฟล์ป้องกันไหม (NOW.md) · มี token/คีย์หลุดไหม
4. รายงาน — เรียงตามความรุนแรง (blocker → major → nit) แต่ละข้อ: ข้อค้นพบ 1 ประโยค (ระบุ ไฟล์:บรรทัด) · ทำไมสำคัญ (ผลที่ตามมา) · หลักฐาน (ขั้นไล่เส้นทางที่เห็น) · แก้อย่างไร (เล็กและชัด) · ปิดด้วยคำตัดสินบรรทัดเดียว: ปล่อยได้ / แก้แล้วปล่อย / ทำใหม่ / ปฏิเสธ + เหตุผลเดียวที่หนักสุด
## กฎ
- ห้ามตอบแค่ "ดูดี" · ถ้าไม่เจออะไรจริง บอกว่าไล่เส้นทางไหน ตรวจอะไรไปแล้ว ให้ผู้ใช้ตัดสินได้ว่าครอบคลุมพอ
- ทุกคำกล่าวเกี่ยวกับโค้ดต้องอ้างไฟล์/บรรทัด ไม่มี "อาจพังเมื่อโหลดสูง" ลอยๆ · แยก "PR/ผู้เขียนบอกว่า X" ออกจาก "ฉันไล่แล้วยืนยัน/หักล้าง X"
- มีปัญหาโครงสร้างให้เปิดด้วยมัน ไม่ต้องเกลี่ยเรื่องสไตล์ · ไม่ชม ไม่อ้อม
- ใช้ทุกครั้งก่อน gh_commit ที่แตะไฟล์ป้องกัน หรือเมื่อผู้ใช้ขอ "ช่วยดูหน่อย"
