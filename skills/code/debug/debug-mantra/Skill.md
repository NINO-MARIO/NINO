# debug-mantra
เมื่อบั๊กยังทำซ้ำไม่ได้ สาเหตุไม่ชัด หรือแก้แล้วอาการเดิมยังอยู่: ท่อง mantra แล้วทำซ้ำ → ไล่เส้นทาง → ล้มสมมติฐาน
## ท่องก่อนเริ่ม (ครั้งเดียวต่อรอบดีบัก ในข้อความแรก ท่องตามตัวอักษร ห้ามย่อ)
> Mantra:
> 1. First is reproducibility. Can the issue be reproduced reliably?
> 2. Know the fail path. Debugger first; then source trace + knob enumeration; then in-code instrumentation.
> 3. Question your hypothesis. What would disprove it?
> 4. Every run is a breadcrumb. Cross-reference all of them.
แปล: ทำซ้ำได้แน่ไหม · รู้เส้นทางที่พัง · อะไรพิสูจน์ได้ว่าสมมติฐานผิด · ทุกครั้งที่รันคือเบาะแส เทียบให้ครบ
ผู้ใช้บอกให้ข้ามบทท่อง → ข้ามการท่อง แต่ยังทำ 4 ข้อเงียบๆ
## ขั้นตอน (ตามลำดับ ห้ามข้าม)
1. ทำซ้ำให้ได้ก่อนเสนอวิธีแก้ — สรุปเป็นสูตรที่รันซ้ำได้: ขั้นตอนกดในแอป / เคสใน tools/test / คำสั่ง `nino diag` ในเทอร์มินัล · พังบางครั้ง = เพิ่มอัตราก่อน (วนเรียก เว้นจังหวะ) · ไม่มีสูตรเลย = หยุด บอกตรงๆ ขอ log จาก `>_` › Console › Logs ห้ามตั้งสมมติฐาน
2. หาเส้นทางที่พัง เรียงขั้น ไม่ข้าม: (ก) อ่าน error จริง (self_diagnose / Console) แล้วไล่โค้ดด้วย gh_outline → gh_grep → gh_read_func (ข) ลิสต์ "ปุ่มปรับ" ทุกตัวที่กระทบผล เช่น provider, โหมด code/roleplay, ค่าใน localStorage, ?safe=1, เว็บ vs APK, ลำดับ script แล้วพลิกทีละตัว (ค) ค่อยใส่ log ชั่วคราวขึ้นต้น [DBG-xxxx] (สุ่ม 4 ตัว) ที่จุดสงสัย
3. สร้าง 3–5 สมมติฐานเรียงตามโอกาส แล้วรัน "วิธีล้ม" ที่ง่ายที่สุดก่อน รอดจึงเชื่อ ตายก็ทิ้ง
4. สมุดเบาะแส: ทุกการทดลองจด journal_note (เปลี่ยนอะไร → เกิดอะไร → ตัดอะไรทิ้ง) สมมติฐานใหม่ต้องอธิบายได้ทุกบรรทัดในสมุด ไม่ใช่แค่รอบล่าสุด · ขัดบรรทัดไหน = ผิดหรือยังไม่ครบ · ไม่แน่ใจ = ออกแบบการทดลองเดียวที่ผลทำให้แน่ แล้วรันอันนั้น
5. แก้จุดเดียว แล้วรันสูตรจากข้อ 1 ซ้ำเพื่อยืนยัน
## กฎ
- ไม่มีสูตรทำซ้ำ ห้ามเสนอวิธีแก้ · ยังไม่ได้ลองล้มสมมติฐาน ห้ามประกาศว่าเจอสาเหตุ
- log [DBG-…] ต้องลบหมดก่อน commit (gh_grep DBG-) ห้ามหลุดเข้ารีโป
- วนเกิน 3 รอบ → หยุดถามผู้ใช้ (ดู qwenchance / anti-loop)
- เครื่องมือเฉพาะของ NINO อยู่ที่ debug-loop · แก้จบแล้วเขียนบันทึกด้วย post-mortem
