# qwen-agent
เมื่องานเป็นกลไกซ้ำๆ ที่ขอบเขตชัด (สรุปไฟล์/log ยาว เปลี่ยนชื่อจำนวนมาก ร่างเทสต์): ฝากโมเดลถูกด้วย delegate
## ใช้เมื่อ (งานกลไก เสี่ยงต่ำ ตรวจผลง่าย)
- ย่อ/สรุปไฟล์หรือ log ยาว · หา+สรุปแบบ grep · เปลี่ยนชื่อ/แปลงรูปแบบจำนวนมาก · ร่างโครง/เทสต์/คำอธิบายให้ · แปลง/จัดรูปข้อความ · ผู้ใช้พูดว่า "ฝากน้อง/ทำแบบถูกๆ/ใช้ qwen"
## ห้ามใช้เมื่อ
- ออกแบบสถาปัตยกรรม · ดีบักที่ต้องใช้วิจารณญาณ · งานเกี่ยวความปลอดภัย/คีย์/ไฟล์ป้องกัน · งานที่ต้องการบริบทของแชทนี้ · งานที่ถ้าโมเดลถูกพลาดแล้วตรวจยาก
## วิธีใช้
1. ต้องตั้งคีย์ 9arm (หรือ TokenMe) ในตั้งค่าแล้ว ไม่มีคีย์เครื่องมือจะบอกเอง
2. delegate {task, files?:["path ในแท็บ Files"], max_tokens?} — โมเดลปลายทาง "ไม่รู้อะไรจากแชทนี้เลย" ต้องเขียน task ให้จบในตัว: ทำอะไร กับไฟล์ไหน ผลลัพธ์รูปแบบไหน เสร็จดูจากอะไร · ห้ามอ้าง "ไฟล์ที่คุยกัน/ข้างบน"
   - ไม่ดี: "จัด import ให้หน่อย"
   - ดี: "ในไฟล์ที่แนบ (api.js) ลบ import ที่ไม่ได้ใช้และเรียงที่เหลือตามตัวอักษร ห้ามแตะโค้ดส่วนอื่น ส่งไฟล์ฉบับเต็มกลับในบล็อกโค้ดเดียว"
3. งบบริบท ~128k โทเคน: เครื่องมือประเมินให้และปฏิเสธถ้าเกิน (ไทยกินโทเคนหนักกว่าอังกฤษ) → งานใหญ่ให้แบ่งทีละไฟล์/ทีละช่วง ส่งแค่ไฟล์ที่จำเป็น ห้ามสั่ง "อ่านทั้งโปรเจกต์" · ผลที่ตกหล่น/ตัด/ไม่ครบทุกไฟล์ = ล้นบริบท ให้แบ่งเล็กลงแล้วลองใหม่
4. delegate ส่งข้อความกลับเท่านั้น ไม่แก้ไฟล์ให้ — ตรวจผลเองก่อน แล้วค่อยลงมือใช้ edit_batch/write_file/gh_edit เอง
5. โมเดลถูกถูกกว่าแต่เชื่อถือน้อยกว่า: ตรวจตามเกณฑ์สำเร็จที่เขียนไว้ใน task ก่อนรายงานผู้ใช้ว่าเสร็จ · ผลแปลก/ว่าง/ไม่ตรงรูปแบบ → ทำเองหรือส่งใหม่พร้อมแก้ task (ไม่เกิน 2 รอบ)
6. ไม่ส่งความลับออกนอกเครื่อง: เครื่องมือปฏิเสธเองถ้าเจอรูปแบบ token/คีย์ แต่ก็อย่าแนบไฟล์ที่มีข้อมูลส่วนตัวโดยไม่จำเป็น
## ไม่แน่ใจ → ทำเอง
- ต้องใช้ทั้งโปรเจกต์ถึงทำถูก = ไม่ใช่งานฝาก
