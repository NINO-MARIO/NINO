# ประตูตัดสินใจ — เมื่อหลายเล่มดูคล้ายกัน เลือกตามเงื่อนไขที่สังเกตได้ (เงื่อนไขแรกที่ตรงชนะ)
หาบั๊ก | ผล error/อาการทำซ้ำได้ในโค้ดหรือเครื่องมือของ NINO → debug-loop ; ทำซ้ำไม่ได้ สาเหตุไม่ชัด หรือแก้แล้วอาการเดิมยังอยู่ → debug-mantra ; แก้จบและพิสูจน์ผ่านแล้วต้องบันทึก → post-mortem
แก้ไฟล์ | จะแก้หลายจุดในไฟล์เดียวให้เร็ว → fast-edit ; ระบบหยุดหรือขึ้น วนซ้ำ → anti-loop ; แก้ไฟล์ครั้งแรกในรอบและยังไม่รู้ว่าใครอ้างถึง → fact-first
แก้หน้าเว็บ | ผู้ใช้ขอสร้างหรือแก้หน้า html → html-workbench ; ปุ่มหรือไฟล์บังกัน/ปุ่มเลือกไฟล์ไม่ทำงานบนมือถือ → ui-fix-mobile
แก้ตัวระบบ | ต้องมีผลในเครื่องนี้ทันทีโดยไม่ผ่านรีโป → self-upgrade ; แก้ผ่านรีโป วิธีคิดและตรวจก่อน commit → self-fix ; รูปแบบคำสั่ง gh_* → github-ops ; ต้องรู้สุขภาพไฟล์ของบ้านก่อนแก้ → home-inspect ; จะลบ/เขียนทับ/ย้อน commit → careful-mode
งานยาว | แบ่งงานใหญ่เป็นเฟสและวัดเป็น % → plan-and-budget ; ก่อนทุกก้าวเมื่อเริ่มวนหรือบริบทตึง → qwenchance ; จะเพิ่ม/ย้ายบล็อกในพรอมต์ระบบหรือสลับโมเดลกลางงาน → prompt-cache ; จบเฟสหรืออยู่รอยต่อของงานแล้วบริบทตึง → compact-at-boundary
หยุดวน | ระบบหยุดแล้วเพราะวนซ้ำ → anti-loop ; ลองเรื่องเดิมครบ 2 ครั้งแล้วยังไม่หาย (ก่อนระบบหยุด) → qwenchance
ดูแลหอสมุด | เล่มโครงสร้างผิดหรือไม่มีสมุดจด → library-audit ; จบงานแล้วได้บทเรียน → notebook-keeping ; สกิลถูกเรียกพลาดหรือเพิ่งเขียนใหม่ → pointer-audit ; ยังไม่มีเล่มที่ตรงงาน → skill-writer
เล่าเรื่องงาน | ต้องบันทึกวิศวกรรมให้ทีม → post-mortem ; ต้องรายงานให้ผู้บริหารหรือ PM → management-talk
วิเคราะห์ก่อนสร้าง | อ่านโครงโค้ดที่มี → code-analysis ; จะเขียนฟังก์ชัน/ไฟล์ใหม่ → reuse-first ; เลือกทางที่ต่างกันมากหรือถามว่าทำไม → decision-record
ตรวจก่อนปล่อย | ไล่เส้นทางโค้ดแบบคนนอกก่อน commit → scrutinize ; หาจุดล้มเงียบ → silent-failure-hunter ; แตะคีย์/อินพุต/เครือข่าย → security-review ; จะบอกว่าเสร็จ → verify-loop
เล่นเกม | อยากเล่นเกมในแอป → amongai ; เล่น Outlaw Immortals → outlaw
