# qwenchance
ก่อนทุกก้าวของงานยาว: ถามว่าวน คิดเกิน หรือบริบทตึงไหม ลองซ้ำไม่เกิน 3 ครั้ง แล้วส่งต่อให้สะอาด
## ก่อนทุกก้าว ถาม 3 ข้อ (ถ้าข้อไหนเข้า ลงมือตามตารางทันที ไม่ต้องคิดยาว)
| ตรวจ | เข้าเมื่อ | ทำ |
|---|---|---|
| วนไหม | กำลังจะซ้ำ (ดูข้างล่าง) | หยุดแล้วเลือกข้อเดียว |
| คิดเกินไหม | คิดเกิน ~1000 คำโดยยังไม่ลงมือ | ตัดสินใจจากสิ่งที่ดีที่สุดตอนนี้แล้วทำ หรือถามผู้ใช้ 1 คำถามคม |
| บริบทตึงไหม | progress_check บริบท ≥ 70% หรือมีสัญญาณ ≥ 2 ข้อ | จบก้าวนี้ แล้วส่งต่อ |
ไม่มีข้อไหนเข้า → ทำก้าวต่อไป
## 1. วนหรือไม่ — เข้าเมื่อข้อใดข้อหนึ่งจริง
- อ่านไฟล์ที่อ่านแล้วในรอบนี้ซ้ำ (และไฟล์ไม่เปลี่ยน) · เรียกคำสั่งเดิมพารามิเตอร์เดิมซ้ำหวังผลต่าง · กลับไปสมมติฐานที่ทิ้งแล้ว · "คิดใหม่ตั้งแต่ต้น" โดยไม่มีหลักฐานใหม่ · 2 ก้าวล่าสุดไม่ได้ข้อมูลใหม่ (อ่านไฟล์ที่เพิ่งแก้เพื่อตรวจ ไม่ถือว่าวน)
- ระบบเตือน "!" ในผลเครื่องมือ (js/loop-guard.js) = สัญญาณวนจริง ปฏิบัติตามทันที
ทำข้อเดียว: (1) บอกสิ่งที่ติดหนึ่งประโยคแล้วถามผู้ใช้คำถามเจาะจง (2) เขียน "รู้อะไร/ไม่รู้อะไร" แล้วทำ "อย่างอื่น" ที่ไม่ใช่ครั้งก่อน (3) วนเรื่องย่อยเดิม ≥ 2 ครั้ง → ประกาศว่ายังแก้ไม่ได้ ข้ามหรือส่งต่อ
- เพดานลอง: คำสั่งที่พังเดิมห้ามรันครั้งที่ 3 · ทำให้ไม่ติดหลัง ~3 ครั้ง (แม้ปรับแล้ว) หยุดถามผู้ใช้ (ระบบหยุดเองที่ 6 ครั้ง นั่นเพดานสุดท้ายไม่ใช่เป้า)
- ห้ามแก้แบบมืด: อ่านให้พอรู้ว่าแก้ถูกก่อนแก้ แก้ 1 ครั้ง → ตรวจ (gh_diff/รันเทสต์) ก่อนก้าวถัดไป
## 2. คิดให้มีขอบ
- ตัดสินใจ → ลงมือ → สังเกต ไม่ทำซ้ำการตัดสินใจที่ทำแล้ว · ตัดสินใจไม่ได้ใน ~1000 คำ = งานกำกวม ถามผู้ใช้ 1 คำถามคม · ไม่ต้องเล่าโจทย์ซ้ำให้ตัวเอง
## 3. บริบท — นับสัญญาณ อย่าเดา
- สัญญาณ: ทำงานมาเกิน ~20 รอบ · อ่านไฟล์ ≥ 5 ไฟล์ หรือมีไฟล์/log ก้อนใหญ่ · ผลเครื่องมือยาวที่ต้องย้อนดู · เหลือขั้นแผน ≥ 3
- นับได้ 0–1 → ทำต่อ · นับได้ 2–4 → ส่งต่อ (จบก้าวปัจจุบันก่อน) · "เหลือก้าวสุดท้ายแล้ว" ไม่ลดจำนวนและไม่ยกเลิกการส่งต่อ
- ก่อนก้าวแพง (อ่านใหญ่ / เริ่มงานย่อยใหม่ / เขียนยาว) ถาม: "เหลือที่พอทำจบและส่งต่อไหม"
## 4. ส่งต่อให้สะอาด
1. วางของที่เก็บถาวรก่อน: gh_diff → gh_commit ที่ผ่านตรวจ (หรือ skill_note) ไม่ให้งานหาย
2. journal_note {task, done[], backlog[], text:สิ่งที่ค้าง+ข้อสังเกต} ให้ครบพอให้รอบหน้าทำต่อได้ (ใช้แทน handoff ของ Claude Code)
3. บอกผู้ใช้ตรงๆ: "บริบทเริ่มตึง ส่งต่อแล้ว เปิดแชทใหม่แล้วพิมพ์ ต่อ"
