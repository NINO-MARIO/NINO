# prompt-cache
เมื่อจะเพิ่ม/ย้ายบล็อกในพรอมต์ระบบ หรือจะสลับโมเดลกลางงาน: ส่วนนิ่งไว้บน ส่วนที่เปลี่ยนทุกรอบไว้ท้าย แล้วตรวจด้วย cache_report
## หลักคิด
- ผู้ให้บริการแคชแบบ "พรีฟิกซ์": ข้อความต้นพรอมต์ที่เหมือนเดิมทุกไบต์ถูกใช้ซ้ำ จุดแรกที่ต่าง = จุดที่แคชหยุด ทุกอย่างหลังจุดนั้นคำนวณใหม่
- พรอมต์โหมดโค้ดจัดเป็น 3 ชั้นโดย js/prompt-cache.js: นิ่ง (กติกา เครื่องมือ สารบัญสกิล) → กึ่งนิ่ง (Skill.md ที่แนบ, สกิลที่ผู้ใช้เรียกเอง) → เปลี่ยนทุกรอบ (FACTS/FILES/REPO/STAGED/JOURNAL/แผนที่โค้ด/โฟกัสงาน) ท้ายสุดใต้หัว "CURRENT STATE"
- Skill.md เปลี่ยน = กึ่งนิ่งเปลี่ยน ส่วนนิ่งยังเป็นแคชอยู่ · ส่วนนิ่งเปลี่ยนเมื่อ: สลับโมเดล/ผู้ให้บริการ, เพิ่ม/ลบเครื่องมือในพรอมต์ (ตั้งคีย์ 9arm/TokenMe, เชื่อม GitHub), สกิลเล่มใหม่เข้าสารบัญ, แก้ข้อความกติกา
## ก่อนเพิ่มบล็อกใหม่ในพรอมต์
1. ถามก่อน: ค่าในบล็อกเปลี่ยนทุกรอบไหม (ขนาดไฟล์ รายชื่อไฟล์ เวลา ตัวเลข %) → ใช่ = ต้องอยู่ท้าย
2. เพิ่มกฎจับบล็อกนั้นในรายการ SEG ของ js/prompt-cache.js (ไฟล์ [ล็อก] ต้องให้ผู้ใช้อนุมัติ) ห้ามแทรกค่าที่เปลี่ยนไว้กลางข้อความนิ่ง
3. cache_report ต้องขึ้น "ส่วนนิ่ง" เท่าเดิมหลังเพิ่ม และ tools/test/browser.test.js ต้องยังผ่าน
## ก่อนทำสิ่งที่ล้างแคช ให้บอกผู้ใช้ตรงๆ (แอปเตือนเองบางจุด)
- สลับโมเดล/ผู้ให้บริการกลางงานที่ยาว (ครั้งแรกหลังสลับต้องคำนวณพรอมต์ทั้งก้อนใหม่)
- เพิ่ม/ถอดเครื่องมือหรือตั้งคีย์ใหม่กลางงาน
- ฝากงานให้โมเดลอื่นด้วย delegate ไม่ล้างแคชของสมองหลัก (เรียกแยก) แต่ผลที่ส่งกลับเข้าบริบทเป็นข้อความท้ายๆ
## กฎ
- ข้อมูลใหญ่ส่งเป็นก้อนผ่านเครื่องมืออ่านเป็นช่วง (gh_read ≤ 220 บรรทัด, read_range) ไม่ยัดทั้งไฟล์ในพรอมต์ · ห้ามใส่คีย์/รหัสผ่านในพรอมต์ (ระบบกันที่ gh_commit/delegate)
- ตัวเลขแคชจริงมาจากผู้ให้บริการเท่านั้น ถ้าไม่รายงาน cache_report จะบอกว่าไม่รายงาน ห้ามประเมินแทน
