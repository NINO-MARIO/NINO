# compact-at-boundary
บริบทตึงที่รอยต่อของงาน: สรุปแล้วตัดบริบท ไม่ตัดกลางงาน
## จังหวะที่ควรสรุป
- หลังสำรวจ ก่อนลงมือ (เก็บแผน ทิ้งผลอ่านไฟล์ดิบ) · หลังจบเฟส · ก่อนเปลี่ยนเรื่อง
## จังหวะที่ห้าม
- กลางการแก้หลายไฟล์ · ระหว่างไล่บั๊กที่ยังไม่รู้สาเหตุ
## วิธี
1. เขียนสรุป: เป้าหมาย / ทำแล้ว (ไฟล์) / ค้างอะไร / ข้อเท็จจริงที่ต้องจำ 2. ทิ้งผลดิบที่เก็บสรุปแล้ว 3. คงบล็อกนิ่งของพรอมต์ไว้บนสุด (ดู prompt-cache) ไม่แก้กลางงาน
- ยึดตามเพดานใน plan-and-budget
