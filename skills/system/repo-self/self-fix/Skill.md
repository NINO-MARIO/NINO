# self-fix
เมื่อจะแก้บั๊กหรือปรับระบบของ NINO ผ่านรีโป: จำแนกก่อน แก้เฉพาะจุด ตรวจก่อน commit ลอง 3 ครั้งไม่ผ่านให้หยุด
## 1. จำแนกก่อนทำ (อ่าน error/บริบทให้ครบ 2 รอบ อย่ารีบแก้นัดแรก)
- บั๊ก → แก้เฉพาะจุด (diff เล็กสุด) · ดีบักตามวินัย debug-mantra
- หนี้ออกแบบ → สร้างไฟล์ใหม่แล้วลบของเก่า ห้ามบวม
- ขาดฟีเจอร์ → เพิ่มในไฟล์เดิม ถ้าเกิน ~50 บรรทัดให้แยกเป็นไฟล์ใหม่ (แล้วเพิ่ม script ใน index.html และบรรทัดใน tools/file-roles.json)
## 2. กฎแก้
1. หนึ่งเรื่อง = หนึ่ง commit (หลายไฟล์ได้ถ้าเป็นเรื่องเดียวกัน เช่น js ใหม่ + script tag + บรรทัดบทบาท) ห้ามผสมหลายเรื่อง
2. ห้ามเขียนทับทั้งไฟล์ ใช้ gh_edit ops เฉพาะจุด · gh_diff ทุกครั้งก่อน commit ว่าไม่เกินขอบเขต
3. อ่านของเดิมก่อนแก้เสมอ ห้ามแก้มืด
4. แตะไฟล์ป้องกัน (รายชื่อใน NOW.md) → ต้องส่ง confirm:true และให้ผู้ใช้กดอนุมัติเอง ห้ามอ้อมด้วยการแก้ไฟล์ที่ตรวจสอบมัน
## 3. รูปแบบที่เจอซ้ำ
| ปัญหา | วิธี | ที่ไหน |
|---|---|---|
| ข้อความไทยผิดในโค้ด | ค้นแล้วแทนเฉพาะคำ (thai-text) | ไฟล์นั้น |
| ไฟล์ใหญ่ > ~500 บรรทัด | แยกโมดูลใหม่ แล้วลดไฟล์เดิม | ไฟล์ใหม่ + ไฟล์เดิม |
| ไม่มีจัดการ error | try/catch + fallback ให้ผู้ใช้เห็น | ฟังก์ชันนั้น |
| ไม่ตรวจชนิดข้อมูล | guard clause หัวฟังก์ชัน | ฟังก์ชันนั้น |
| โค้ดซ้ำ ≥ 3 ที่ | แยก helper แล้วเรียกทุกจุด | ไฟล์ helper + ที่เรียก |
## 4. ตรวจหลังแก้
- gh_diff ไม่เกินขอบเขต · ไวยากรณ์ผ่าน (self_diagnose / gh_diagnose) · แก้ html ปิดแท็กครบ · แก้ css วงเล็บคู่ · ชื่อไม่ซ้ำข้ามไฟล์ (find_dup_globals.js) · ข้อความ commit อังกฤษสั้นบรรทัดเดียว
- รายงาน sha + บอกผู้ใช้รอ deploy ~1 นาทีแล้วรีเฟรช
## 5. ติดแล้วทำอย่างไร
- ลอง 3 ครั้งแล้วยังไม่ผ่าน → หยุด อธิบายผู้ใช้ 3 สาเหตุที่เป็นไปได้ · ห้ามวนแก้โดยไม่อ่าน error ใหม่ · ห้ามทิ้ง "เดี๋ยวค่อยแก้" — เริ่มแล้วต้องจบหรือย้อนคืน (gh_discard / gh_restore)
- คู่มือที่เกี่ยว: anti-loop · qwenchance · scrutinize
